Act I · The sampler

Each token is one forward pass, then one draw.

p(xt | x<t)

The pass computes the next-token distribution given everything before it. The sampler draws xt, appends it, and the pass runs again.

Running example

GPT-2 small, after The capital of France is. One lab per stage, on your laptop.

Speaker notes · 4 min

Write p(x_t | x_<t) on the board before you show the slide and leave it there: “the probability of the next token given everything before it”. The product of these conditionals is the probability of the whole text; that is the chain rule, so writing one token at a time loses nothing. What limits a model is how well the network learns each conditional.

Predict question: “Is writing a text one token at a time a simplification that loses something?” No: the factorization is exact.

Talk track: this graph is the whole act. Walk it once from left to right, then say that each box is one of the next slides, with its lab or demo named under it. The bracket marks the forward pass, the network itself; the tokenizer and the sampler sit outside it.

Background for you, not for the slides: Andrej Karpathy, Deep Dive into LLMs like ChatGPT (YouTube), covers the same arc at greater length.

Speaker notes · 5 min

Talk track: point at the x_t on the board. Each x_t is an integer ID from a vocabulary of 50,257 entries. A token is a word, a piece of one, a few digits or a character. The model never sees s, t, r: it sees 41236.

Qualification to keep: models learn some spelling facts about tokens from text that spells words out, so letter counting is unreliable rather than impossible.

Stage 2 · Transformer

Attention: each token looks up the tokens before it.

In
five IDs, each looked up as a vector
Out
five vectors; the last one scores the next token

softmax(QKT/√d)·V: each token’s query is matched against the keys of itself and earlier tokens, and returns a mix of their values. Then an MLP; ×12 layers.

Lab · 4 minutes

Open the attention lab

Drag the query to one key. Then GPT-2: “it” puts 84.7% on “animal”.

GPT-2 small: 12 layers of 12 heads; weights recorded in fixtures/attention.json (openai-community/gpt2 at 607a30d, 2026-10-10). The lab’s toy panel is illustrative.

Speaker notes · 6 min

Talk track: a dictionary lookup is hard: exact key, one value. Attention makes it soft and differentiable: every key gets a similarity score, softmax turns the scores into weights that sum to 1, and the output is the weighted average of the values. d is the key dimension; dividing by √d keeps the scores from growing with it. Causal: a token looks only at itself and earlier tokens, which is what keeps each factor p(x_t | x_<t).

Each head runs its own lookup in parallel; stacking layers lets later lookups use earlier results. Keep the words key and value: Act III comes back to them with the KV cache.

Activity: two minutes on the toy, two on GPT-2 (layer 5, head 4). Predict question before they drag: “If the query points exactly at one key, does the output equal that key’s value?” Only as the scale grows; at the default scale the other values still pull the output. Most heads do nothing human-readable; the lab opens on the one that links “it” to “animal” most.

Transition: “After the last layer, the network gives one number per vocabulary entry.”

Stage 3 · Logits

One forward pass gives a distribution, not an answer.

p = softmax(z/T) over 50,257 scores z, at temperature T.

Lab · 6 minutes

Open the next-token lab

Bet, lock in, reveal. Then move T and top-p.

Recorded: T = 1 over the full vocabulary, from the logits and log-sum-exp in fixtures/next_token.json (GPT-2 small, 2026-10-10). The top 20 hold 45.7% of the mass.

Speaker notes · 7 min

Talk track: GPT-2 does not answer “Paris”. It returns probabilities, and “ Paris” is fifth at 3.2%, behind “ the” at 8.5%, because “The capital of France is the city of Paris” is also a good continuation. The answer appears only when the sampler draws.

Write softmax(z/T) next to the equation on the board: divide the scores by T, exponentiate, normalize. Low T piles mass on the top token; T → 0 is argmax, the same token every time; high T spreads it out.

Activity: on a shared screen, collect three or four guesses and lock each; the tally is local to the browser. Reveal, then compare the class’s top guess with GPT-2’s. In the sandbox, move T from 1 to 0.3, then to 2, and set top-p to 0.5: which candidates can never be drawn? Point out the honesty note: only the top 20 logits are stored, so the sandbox renormalizes among them.

Transition: “A distribution is not a token yet. Something has to draw.”

Stage 4 · Sampler

The sampler draws: same prompt, different answer.

  • Each answer is a draw; a peaked distribution can still repeat.
  • A seed or argmax reproduces locally. Hosted, you cannot fix the seed.
  • Do not judge an agent from one run.

Demo · 3 minutes

demos/model/sampling.md: one prompt, five runs.

Recorded 2026-10-11: claude-haiku-5-5 5 of 5 distinct; gpt-6-luna 4 of 5.

As of 2026-10-18, neither CLI exposes a temperature, top-p or seed option: Claude Code and Codex CLI references; --help of Claude Code 2.1.302, codex-cli 0.162.1.

Speaker notes · 5 min

Run the sampling runbook: predict question “Same prompt, same model, same settings, five times. How many different names do we get?”, hands for 1, 2–3 and 4–5, then uv run sampling.py (or --via codex). Fallback: uv run --offline sampling.py --replay.

Report whatever count you get. A live run can repeat a favourite name; that is a peaked distribution, not determinism.

Talk track for reproducibility: local and seeded, outputs reproduce; hosted, you cannot fix the seed and should not rely on even temperature-0 outputs being bit-identical, because batching on shared GPU servers can change the order of floating-point additions. Keep what you need to reproduce (code, data, solver logs) in files.

If there is time, back in the next-token lab: Sample ×100 twice, then Argmax. Predict first: “Will two batches of 100 give the same counts?” No in Sample mode; yes in Argmax mode.

Stage 5 · Append and repeat

Append the token, run the pass again.

In
The capital of France is + ␣the
Out
a context one token longer: the next pass

The loop stops at an end-of-sequence token or a length limit.

Speaker notes · 6 min

Talk track: each Step is the whole graph once. One forward pass computes p(x_t | x_<t), the seeded sampler draws, the token is appended, repeat. A chat model’s answer is this loop with a much larger model. The lab’s list “What one Step computes” walks the same stages.

Activity: everyone generates a story. Ask two people with different seeds to read their first line aloud: same prompt, same model, different stories. Then click a token in the middle to rewind and resample.

Predict question before the reset: “Same seed, same settings, same clicks: same text?” Yes. That is the local reproducibility the hosted agents do not give you.

Transition: “The graph is the same for every model. What differs is the weights. Where do they come from?”

Where the weights come from

Pretraining makes a document continuer. Post-training makes an assistant.

Neither stage checks facts: the false line reads as fluently as the true one.

Recorded 2026-10-10 by fixtures/build_fixtures.py into fixtures/base_vs_instruct.json: HuggingFaceTB/SmolLM2-135M at 93efa2f097d58c2a74874c7e644dbc9b0cee75a2 and HuggingFaceTB/SmolLM2-135M-Instruct at 12fd25f77366fa6b3b4b768ec3050bf629380bac, greedy decoding, max 48 new tokens.

Speaker notes · 5 min

Predict question, before you reveal the right column: “Same question, a model of the same size. What does the base model write after it?” Many will expect a plain answer.

Talk track: pretraining minimizes −log p(x_t | x_<t) over a vast amount of text; the result is a base model, a document continuer. Prediction is compression (Delétang et al., Language Modeling Is Compression, 2023); Karpathy’s “lossy zip file of the internet” is the image for what the weights keep. Post-training, supervised fine-tuning on conversations then preference tuning, teaches the role and the format: answer, then stop. The third stage, RL with verifiable rewards (term from Lambert et al., Tülu 3; at scale in DeepSeek-R1), is Act II’s.

The base model gets the capital right, then keeps going because the most likely document is a quiz page: it invents the next question and a false answer about New Zealand. The excerpt is the first three lines of its 48 tokens; the instruct input used its chat template. The instruct model answers and emits end-of-sequence: the loop’s stop token.

Hallucination is structural: the objective is likelihood, not truth, so a false continuation is produced the same way as a true one. The weights also stop at a training cutoff; an agent that reads the installed docs or runs --help gets the current API, because those tokens are part of x_<t. The check has to come from outside the model: tests, a source, a solver.

Transition: “Let us name what we have seen all act.”

Close · System 1

Every token came from one forward pass: System 1.

  • Fixed compute per token: the same layers run once, however hard the question.
  • Not zero reasoning: a pass can chain a few steps, but its depth caps how many.
  • A longer context makes a pass slower, not deeper.

Next · Act II

Run the pass in a loop: the model writes tokens it then reads, and spends more compute on a hard problem.

In-pass multi-step reasoning: Jack Lindsey et al., On the Biology of a Large Language Model, “Multi-step Reasoning”, transformer-circuits.pub, 2025-03-27.

Speaker notes · 2 min

Talk track: point at the bracket. The model is p(x_t | x_<t) plus a sampler. For a given model, context and configuration, each token gets a fixed amount of computation: System 1, fast and fluent, with no step where it decides to think harder about a hard token. The label is Kahneman’s, used as a metaphor; Act II says so.

Be precise. A pass is not empty of reasoning: Lindsey et al. trace a two-hop chain (Dallas, then Texas, then Austin) inside one forward pass. But the number of such steps is bounded by the depth and does not grow with difficulty. A longer context costs more time per pass; that is reading more, not reasoning more.

Transition into Act II: “If one pass cannot think longer, how do reasoning models and agents solve hard problems? They run this pass in a loop. That is the next act.”
