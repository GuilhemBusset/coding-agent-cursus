Test-time compute: System 2 as search

Each extra token or extra sample buys more serial or parallel compute at answer time. Reasoning then behaves like an anytime search: it improves as the budget grows, but only as far as the thing that picks the answer, the verifier, can take it.

How to read this lab. Every chart is an illustrative simulation. The charts are computed in your browser with JavaScript from the closed-form formulas printed in each panel. No model was run and no randomness is used, so the same settings always give the same numbers. The shapes follow the cited papers; the numbers are not theirs.

1 · Best-of-N: sampling is cheap, selecting is not

Illustrative simulation, not a measurement. The problem set is a Beta distribution of success rates, not a benchmark, and no model was sampled.

Ask the same model N times. If one of the N answers is right, the problem is covered. Whether you actually ship that right answer depends on how you pick: by majority vote, or with a verifier that sometimes accepts wrong answers. An OR reader can see each curve as an anytime search: more samples never hurt coverage, but the selection rule sets the ceiling.

pass@N = E[1 − (1 − p)N] = 1 − B(a, b + N) / B(a, b), with p ~ Beta(a, b)

  • Each problem has its own success rate p, drawn from Beta(a, b). Given p, the N samples are independent. K is the number of correct samples, so K follows a beta-binomial law.
  • Coverage is P(K > 0), which is the formula above. It is not 1 − (1 − E[p])N: with p uniform, pass@2 is 2/3, not 3/4.
  • Majority vote uses a binary model: every wrong sample gives the same distractor answer, a single wrong answer, which is the hardest case for voting. The correct answer wins with a strict majority of correct samples, and a tie counts half (½).
  • Verifier: true-positive rate 1 (it never rejects a correct sample) and false-positive rate f (it accepts each wrong sample with probability f). The page picks uniformly among accepted candidates, which is the same as taking the first accepted one in random order. Success = ΣK P(K) · E[K / (K + W)], with W ~ Bin(N − K, f). K = 0 contributes 0, because anything accepted is then wrong.
  • Limits as N → ∞: coverage → 1, majority → P(p > ½), verifier → E[p / (p + f · (1 − p))].
Mean p = a / (a + b)20.0% Coverage at N71.8% Majority vote at N11.7% Verifier at N53.6%

As N → ∞: coverage → 100%, majority → 10.2%, verifier → 54.7%.

Predict, lock in, then reveal

With a 10% false-positive verifier, as N grows without bound, which curve's limit is 100%?

Answer: coverage only.

Any problem with p > 0 is eventually solved by some sample, so coverage tends to 1. In the limit, majority vote tends to P(p > ½): a problem the model gets right less than half the time is lost to the distractor however many votes you take. The verifier tends to E[p / (p + f(1 − p))], which stays below 1 when f > 0, because the wrong samples it lets through grow in step with the right ones. Set f to 0 and the verifier curve lies on top of coverage; set f to 1 and it stays at the mean p.

2 · The effort dial: more thinking, by difficulty

Illustrative simulation, not a measurement. The accuracy curves are invented sigmoids and the price is an illustrative price, not a vendor quote.

Reasoning models let you set how many tokens they may think for. Thinking tokens are serial compute: each one is another pass through the network. Snell et al. found that how much extra test-time compute helps, and how best to spend it, depends on how hard the prompt is, and that it pays off most where the model already has a non-trivial success rate. The curves below stylize that: easy problems saturate early, hard ones need far more tokens and still plateau lower. Some tasks go the other way: past a point, longer reasoning makes the answer worse.

accd(x) = floor + (ceild − floor) · σ(s · (x − md)), with σ(z) = 1 / (1 + e−z) the sigmoid and x = log2(thinking tokens)

  • floor = 0.05, slope s = 1.2. The dial runs from x = 7 to x = 15 (128 to 32,768 thinking tokens).
  • easy: ceil 0.95, midpoint m 8 · medium: ceil 0.85, m 10.5 · hard: ceil 0.6, m 13.
  • Inverse-scaling task: acc(x) = 0.05 + (0.8 − 0.05) · σ(1.2 · (x − 9)) − 0.1 · max(0, x − 11). The penalty starts at the peak, x = 11, and removes 0.1 per doubling of tokens.
  • Cost per problem = thinking tokens × 10 $ / 1,000,000 tokens. This is an illustrative price, not a vendor quote; the cost axis is on top of the chart.

Predict, lock in, then reveal

On the inverse-scaling task, what does doubling thinking tokens past the peak do?

Answer: accuracy falls, and you pay double for it.

In this model accuracy peaks at about 74% near 2,048 tokens and falls to about 40% at 32,768 tokens: each doubling past the peak adds a 10-point penalty that the saturated sigmoid no longer offsets. Gema et al. built real tasks with this shape: longer reasoning let models get distracted by irrelevant details or latch onto spurious features. For an agent, the highest effort setting is not automatically the safest one; measure it on your own task.

3 · Base vs RL-tuned: sharpen or expand?

Illustrative simulation, not a measurement. Both models are invented Beta mixtures chosen to show the shape of the debate. They are not fitted to any paper's data.

Reinforcement learning with verifiable rewards makes a model much better at pass@1. Yue et al. reported that, at large k, the base model's pass@k catches up and overtakes, and read this as RL sharpening what the base model could already do rather than expanding it. That reading is contested: Liu et al. (ProRL, arXiv 2505.24864) report prolonged RL runs that solve problems the base model fails at however many attempts it gets. Treat the crossing below as one possible shape, not a settled fact.

pass@k = Σi wi · [1 − B(ai, bi + k) / B(ai, bi)] for a mixture Σi wi · Beta(ai, bi)

  • base = 0.6 · Beta(1, 3) + 0.4 · Beta(0.5, 8)
  • RL-tuned = 0.6 · Beta(4, 1) + 0.4 · Beta(0.08, 8)
  • RL moves the reachable problems toward p near 1 (sharpening) and pushes the hard tail toward p near 0. Every Beta component has a positive density on (0, 1), so in this model no problem is unsolvable for either model: the RL curve still tends to 100%, but it converges slowly because of its small-a component, Beta(0.08, 8).
Base pass@k17.4% RL-tuned pass@k48.4% First k where base ≥ RL12

Predict, lock in, then reveal

At k = 1,024, which model solves more problems in this illustrative mixture?

Answer: the base model, about 96% against 73% for the RL-tuned model.

RL wins at pass@1 because it concentrates probability on problems it can already solve, but the problems it pushed toward p ≈ 0 need a huge number of attempts. This is the output of a model built to show the debate, not measured data, and the sharpen-or-expand reading is contested.

For an agent: a single run reflects the tuned behaviour, while retries and parallel attempts can recover some of the breadth of the base model.
