Context lab: what the model sees and what it costs

The model is a pure function of its context. The harness re-sends the whole transcript every turn, so everything you add is paid for again and stays in the window until something removes it.

The chat view shows one question, one tool use and one answer. The raw view shows what the harness actually sends: a request shaped like the Anthropic Messages API, with the system prompt and tool schemas in front of every turn.

Call 1: the model decides to read the log
Input: system + tools + user = 160 estimated tokens. Output: the tool call, 32 estimated tokens.
Call 2: the model answers
Input: everything from call 1, its tool call and the tool result = 270 estimated tokens. Output: the reply, 48 estimated tokens.

The model keeps nothing between the two calls. Call 2 works only because the harness sends call 1's input again, plus the tool call the model wrote and the result the harness got back.

Panel 2

What it costs over thirty turns

Each turn adds one short user message and one reply. The new message never grows, but the request does: turn t carries every earlier message and reply as input. Prompt caching bills the repeated prefix at a lower rate. It does not remove it.

Predict before you look

Message 30 is as long as message 1. Why does it cost more?

Answer: the whole transcript is re-sent.

The model keeps no memory between calls: for a fixed model and settings, its reply depends only on the context it receives. So the harness sends everything again. In this scenario turn 30's request is 33,200 input tokens for a 200-token message: the system and tool prefix, plus all earlier messages and replies. Prompt caching bills most of that repeated prefix at the cache-read rate, which makes it cheaper, but the tokens are still sent, still billed and still fill the window.

Illustrative simulation, not a measurement. The conversation sizes are invented (see the constants table). The prices are documented list prices for Claude Sonnet 5.5, as of the date in the caption.

It = P + U + (t − 1)(U + A), with P = 4,000 (system + tools), U = 200 (user message), A = 800 (reply, including its tool traffic)

without caching: costt = It × input price

with caching: turn 1 writes I1; turn t > 1 reads It−1 and writes the new U + A

  • Assumptions: every turn arrives within the 5-minute cache TTL (time to live), so nothing expires.
  • One cache breakpoint sits on the last block of each request, so the whole previous request is the cached prefix.
  • The prefix is above the model's minimum cacheable length.
  • Output tokens are excluded: they are billed separately at the output rate, in both modes.

Panel 3

The context budget

A meter modeled on Claude Code's /context command, which breaks the window into categories. Try the actions and watch what fills the window and what frees it.

Illustrative simulation, not a measurement. Every allocation and action size is invented. Only the two window sizes are documented. Autocompact here is a simplification: when the used tokens pass the window minus the buffer, messages shrink to the size of a compact summary. The real harness summarizes with a model call and re-attaches some files and skills.

The MCP action is an upfront-loading scenario: a server whose full tool schemas enter the context at once. Current Claude Code defers MCP tool definitions by default and uses tool search, so only tool names load until a tool is used (Claude Code docs, costs).

Context window
Context window of 200,000 tokens: 35,000 used, 135,000 free, 30,000 held as autocompact buffer.

In Claude Code, /context shows this breakdown, /compact summarizes the conversation and /clear starts a new conversation with empty messages. In Codex, /status shows the remaining context capacity, /compact summarizes, and /new starts a new chat (/clear also does, after clearing the terminal). Both harnesses compact automatically near the limit. Commands checked against the Claude Code and Codex docs on 2026-10-16.

A full window is not the only cost. Recall degrades as the context grows, even on simple retrieval tasks, and it degrades faster when the relevant passage looks less like the question. That is why the actions that keep the window small (compaction, clearing, delegating to a subagent with a short summary) matter before the limit, not only at it. Sources: Chroma, Context rot (2025-07-14); Anthropic, Effective context engineering for AI agents (2025-09-29). This lab draws no recall curve: neither source publishes one universal curve to copy.
