World models: open loop vs closed loop

A plan made inside an imperfect model drifts away from reality unless you look at what actually happened and plan again. For a coding agent, the tests and the tool output are what it looks at.

Plan once, or replan from what you observe

Illustrative simulation, not a measurement. The world, the learned model, the seed and every number in this panel are invented for teaching. No robot or agent was run to make it.

A point mass starts on the left and must reach the goal on the right without touching the obstacle. The planner never sees reality directly. It searches for actions inside a learned dynamics model, then those actions are executed in the real world.

Reality (hidden from the planner): v′ = 0.75 v + 1.3 u, then p′ = p + 0.2 v′, with |u| ≤ 1 per axis.

Learned model: s′ = A s + B u + c, with state s = (x, y, vₓ, vy) and action u = (uₓ, uy).

The model is a least-squares fit to 200 training transitions sampled from the simulator with seed 20261011. The simulator has no noise, so every seed recovers reality exactly. The model error slider then corrupts the fit on purpose: the model believes the controls are rotated and stronger than they are, and that a current pushes the point upwards. Reality never changes.

The planner is the cross-entropy method (CEM). It samples N = 60 action sequences of H = 30 steps from a Gaussian, rolls each one through the learned model, keeps the K = 8 cheapest, refits the Gaussian to them, and repeats I = 12 times. The cost is the distance from the goal after H steps, plus 20 for each path segment that touches the obstacle, plus 0.001 × Σ|u|².

  • Open loop plans once at step 0, then executes all 30 actions without looking.
  • Closed loop starts from the same plan. At every step it observes the true state, replans from there, and executes only the first action of the new plan.
0.50: controls rotated 20°, gain ×1.15, believed current 0.075 per step

The seed sets the training sample and every random draw of the planner. Changing the seed, the error or the added mass in panel 2 stops a run and returns to step 0.

Try this

  1. Set the model error to 0 and run. With a perfect model both loops reach the goal; planning once is enough.
  2. Back at the default error of 0.50 and the default seed, the open loop's dashed prediction still ends in the goal, but the real path drifts into the obstacle. The closed loop makes the same first mistake, sees it, and corrects it.
  3. Push the error to 1.00 and try a few seeds. Feedback still helps, but with a model this wrong the closed loop sometimes fails too.
Learned and corrupted coefficients

A is unchanged by the model error: the model's picture of how position and velocity carry over is right. The error changes B (how actions move the point) and c (a current that is not there).

Planner details

Actions are clipped to [−1, 1] per axis. A fresh plan starts from a zero mean with spread 1. Each closed-loop replan starts from the previous plan shifted by one step, plus a final action that stops the predicted motion, with spread 0.2.

The cost only looks at where the plan ends after H steps, so it never rewards arriving sooner. A replanner can then postpone arrival forever, always planning to arrive H steps from now. To prevent that, the sampling spread is wide only for actions before step 15, or the next 4 steps once step 15 has passed, and 20 times narrower after it. The planner commits to arriving and then holding position.

Every random draw comes from a seeded mulberry32 generator, so a seed, error and step always give the same picture.

Kepler without Newton: a fit that matches until the world changes

Illustrative simulation, and a stylised analogy. The units, masses and orbits are invented. This is not a reproduction of the transformer experiments in Vafa et al. (2025); it borrows their framing to show the same kind of failure in a few lines of arithmetic.

Two test particles orbit a fixed central mass. Reality is Newtonian gravity, integrated in steps of 0.01 time units. The predictor knows no physics. For each orbit it fits a periodic curve to the positions seen up to t = 16, then it is frozen. It is never refitted.

x̂(t) = a₀ + Σh=1…8 [ah cos(2πht/T) + bh sin(2πht/T)], and the same form for ŷ(t).

The period T and the coefficients are chosen by least squares. Error = largest distance between truth and fit over 16 < t ≤ 32, divided by the orbit's size.

The fitted periods are 4.50 and 8.11 time units.

0.000: no added mass

Worst held-out error: 0.3% of orbit size (inner 0.0%, outer 0.3%). The frozen fit still predicts both orbits.

The fit reproduces what it was shown almost perfectly, yet it holds no idea of a force. When a new mass appears, the true orbits bend and the fit carries on drawing the old ellipses. Vafa et al. report a related result for transformers trained on orbital trajectories: they predict well, but when adapted to new physics tasks they fail to apply Newtonian mechanics and behave as if they had learned task-specific heuristics.

What this means when you drive a coding agent

A coding agent plans against a model too: its picture of your repository. The parts of panel 1 map onto the agent loop, whichever agent you use.

The learned dynamics model panel 1's s′ = A s + B u + c
The agent's picture of your repo: what it believes the code does, how the modules connect, how to build and test it. It is fitted from the files and output it has read so far. Like the corrupted model, it is plausible and partly wrong, and the plan it produces looks fine on paper: the dashed line still ended in the goal.
The observation the true state after each step
Test output and tool output: a failing test, a compiler error, a stack trace, the actual diff, the result of running the program. This is reality reporting where you really are, as opposed to where the agent's picture says you are.
Replanning every step the closed loop
The agent loop: make a small change, run the tests, read the output, replan from what actually happened. Open loop is writing the whole change from the first read and never running it; with the default settings of panel 1, that is the run that hit the obstacle.
A frozen fit panel 2
A picture that matched everything seen so far can still break when something it never saw changes: a new dependency, a migration, a config flag. Agreement with the past is not understanding; only a fresh observation tells you the world moved.

Feedback helps; it is not a guarantee. At high model error the closed loop sometimes fails as well. If every test run surprises the agent, looping faster will not fix it. Improve the picture instead: point it at the code that matters, explain the architecture, or have it read before it writes.

  • Give the agent a fast, trustworthy check it can run itself, and ask it to run that check after every change.
  • Prefer small steps with an observation after each one over one large plan executed blind.
  • Read the observation yourself when the agent's summary and the tool output disagree. The output is the ground truth.

Sources and framing

  • Keyon Vafa, Peter G. Chang, Ashesh Rambachan, Sendhil Mullainathan, What Has a Foundation Model Found? Using Inductive Bias to Probe for World Models (arXiv 2507.06952, 2025). Models trained on orbital trajectories predict them well but fail to apply Newtonian mechanics when adapted to new physics tasks. Panel 2 is a stylised analogy, not their experiment.
  • Mido Assran et al., V-JEPA 2: Self-Supervised Video Models Enable Understanding, Prediction and Planning (arXiv 2506.09985, 2025). A video world model learned mostly from internet video, then action-conditioned on a small amount of robot video and used to plan robot arm actions towards image goals. It is a learned simulator used for planning, as in panel 1.
  • Yann LeCun, A Path Towards Autonomous Machine Intelligence (OpenReview, 2022). A position paper, not an empirical result, proposing agents built around a predictive world model and planning.
  • Planning by sampling with the cross-entropy method and replanning at every step (model-predictive control) is standard control practice; panel 1 uses the textbook form.
