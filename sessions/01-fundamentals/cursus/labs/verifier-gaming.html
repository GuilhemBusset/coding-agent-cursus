Verifier gaming

An agent optimizes what you check, not what you asked for. Three sandboxes: a scorer with a leak, an “optimal” you can certify or not, and three patches that all turn the tests green.

The case behind the lab

The paper reports the phenomenon in general terms. It does not describe the packing scorer below: that sandbox is an invented analogy for one kind of leaky verifier, a check that tolerates a small violation. The fix is familiar from operations research. Ask for a certificate, something you can check exactly and cheaply, instead of trusting the score.

Panel 1

A scorer that tolerates overlap

Illustrative: the agent, the squares, the scorer, the seed and every score in this panel are invented for teaching.

An agent packs four 100 × 100 squares into a row and wants the highest packing score = 400 ÷ bounding width. A tight, legal packing scores exactly 100%. The scorer checks overlap with a tolerance: it accepts any layout whose largest overlap is at most the tolerance. The agent hill-climbs: each step tries the six moves that widen or narrow one gap by 1, in an order drawn from seed 1729, and keeps the first move the scorer accepts that raises the score. It stops when no such move exists.

    What to try and what it shows
    1. Run with the tolerance at 0. The squares close up and the score stops at 100%: an honest packing.
    2. Raise the tolerance to 7 and run again. Every accepted move passed the scorer, and the agent ends with every gap at −7 and a score above 100%: a score no legal packing can reach. Nothing in the trace looks like cheating; each step is a small, accepted improvement.
    3. Tick the exact checker. Overlap is no longer accepted, so the same seed stops at 100% whatever the tolerance.

    The agent never “decided” to cheat. The tolerance made overlap the cheapest way up, so the search converged on it.

    Panel 2

    Four agents say “optimal”

    Illustrative: the LP, the agents and their claims are invented for teaching.

    Each agent returns a primal solution and a dual solution as its evidence. Weak duality says any feasible dual solution bounds every feasible primal objective from above. So a claim is certified optimal only if both witnesses are feasible and the duality gap, bound − objective, is 0. You recompute all of it; nothing rests on the agent’s word.

    Primal

    maximize 3x + 2y

    subject to x + y ≤ 4

    x ≤ 2

    y ≤ 3

    x, y ≥ 0

    Dual

    minimize 4u + 2v + 3w

    subject to u + v ≥ 3

    u + w ≥ 2

    u, v, w ≥ 0

    Agent A

    “This solution is optimal.”

    Primal witness: x = 1, y = 3

    Dual witness: u = 2, v = 1, w = 0

    • Primal feasible: yes
    • Dual feasible: yes
    • Primal objective (3x + 2y): 9
    • Dual bound (4u + 2v + 3w): 10
    1

    Agent B

    “This solution is optimal.”

    Primal witness: x = 2, y = 2

    Dual witness: u = 2, v = 1, w = 0

    • Primal feasible: yes
    • Dual feasible: yes
    • Primal objective (3x + 2y): 10
    • Dual bound (4u + 2v + 3w): 10
    0

    Agent C

    “This solution is optimal.”

    Primal witness: x = 3, y = 0.5

    Dual witness: u = 2, v = 1, w = 0

    • Primal feasible: no
    • Dual feasible: yes
    • Primal objective (3x + 2y): 10
    • Dual bound (4u + 2v + 3w): 10

    Certificate unavailable. The primal witness violates x ≤ 2 (x = 3), so there is no feasible solution to certify and no gap to show. The matching numbers prove nothing.

    Agent D

    “This solution is optimal.”

    Primal witness: x = 2, y = 2

    Dual witness: u = 1, v = 3, w = 0

    • Primal feasible: yes
    • Dual feasible: no
    • Primal objective (3x + 2y): 10
    • Dual bound (4u + 2v + 3w): 10

    Certificate unavailable. The dual witness violates u + w ≥ 2 (1 + 0 = 1), so its 10 is not a valid bound and no gap can be read from it.

    Your call: which claims are certified?

    Agent A’s “optimal”

    Both witnesses are feasible, but the gap is 1: the dual only proves the optimum is at most 10, and A reached 9. Agent B’s (2, 2) shows 10 is reachable.

    Agent B’s “optimal”

    Both witnesses are feasible and the gap is 0: no feasible solution can beat 10, and (2, 2) reaches it. That is a certificate you checked yourself.

    Agent C’s “optimal”

    Objective and bound both read 10, but x = 3 breaks x ≤ 2. An infeasible point can match any bound; check feasibility before the gap.

    Agent D’s “optimal”

    The primal point is the true optimum, yet the evidence fails: the dual breaks u + w ≥ 2, so its 10 bounds nothing. A right answer with a broken certificate is still unverified.

    Panel 3

    Catch the agent

    Illustrative: the code, the test and the three patches are invented for teaching.

    The task: make sum add up its numbers. The test fails on the code below. Three agents each return a patch, and with each patch applied the displayed test passes. Only one of them did the task.

    Classify each patch

    Patch A

    It changes the expected value from 5 to 2, the wrong answer the broken code already gives. The code is untouched and still counts instead of adding.

    Patch B

    It adds the values for any input, including the empty list, and leaves the test alone. A second test such as sum([7]) still passes.

    Patch C

    It returns 5 exactly when the input is the test’s input, [2, 3], and keeps the bug everywhere else: sum([7]) still returns 1.

    The tells, and how to check a real agent’s work
    • Test edit: run git diff --stat first. If a fix touches sum.test.js or anything under tests/, read that part before the code. The lab ladder’s L2 rule applies: the tests are the verifier, and the agent does not edit them.
    • Hard-code: look for the test’s own input or expected literal ([2, 3], 5) in implementation code. Add one input the agent never saw; sum([7]) exposes it.
    • Honest fix: the change is general, the tests are untouched, and inputs the agent never saw still pass.

    References

    • Georgiev, Gómez-Serrano, Tao, Wagner, Mathematical exploration and discovery at scale, arXiv 2511.02864 (v3, 2025-12-22). The quotation above is from §4.
    • Jason Wei, Asymmetry of verification and verifier’s rule, jasonwei.net, published 2025-07-15. Wei’s framing (the post’s address still calls it the verifier’s law): “The ease of training AI to solve a task is proportional to how verifiable the task is.” This lab adds the corollary: an agent gets good at whatever your verifier actually measures.
