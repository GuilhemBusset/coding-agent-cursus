## What the page is

The agent-loop replay widget: it replaces the static "what is an agent" diagram, and it is the
fallback player for the Act III live demos. Issue #41 built the first version. Issue #47 added the
task recordings, the lane, the meter, prediction points and side by side.

Data, all inline and generated by `../../fixtures/runs/normalize_runs.py` (the page uses no
fetch, CDN or remote font):

- `agent-runs`: a byte copy of `../../fixtures/runs/agent-demos.json`, the demo catalog
  (schema 1, 26 runs from `../../demos/agent/recorded/`).
- `agent-run-recordings`: every committed `agent-run/1` recording (`flipped-sense`,
  `impossible` and `context-bomb`, each in Claude Code and Codex). That is 6 runs and 192 steps,
  59 of them clipped at 1,200 characters. Meta, totals, tool inputs and per-step tokens are copied
  unchanged.

Behaviour:

- One native, labelled `<select>`, with a group for the recorded tasks and one per demo. `#run=<id>`
  preselects any of the 32 runs, so the runbooks' Fallback links keep working.
- One toolkit `[data-stepper]` per run. Each step shows its type badge (thought, tool call, tool
  result, message), the tool, exit code, error flag, arrival offset when recorded, and the text.
- **Lane.** Gather, act and verify, with the current step's phase marked `aria-current="step"`.
  The page reads the phase from the tool name and command alone:
  - an edit tool or a shell write is act;
  - a test run, `uv run …py` or `git diff`/`status` is verify once the agent has changed
    something, and gather before that (it reproduces the failure);
  - everything else is gather;
  - thoughts, results and messages keep the phase of the last call.

  The page says it is a reading aid.
- **Meter.** Only Claude Code's stream reports usage per model call (on its first step). For those
  runs the meter shows:
  - the context sent with the latest call (its input, including cached), as a `<meter>` scaled to
    the run's peak, not to a context window;
  - the input sent so far, which ends exactly at the CLI's total (context-bomb: 373,202 tokens of
    context, but 4,889,658 tokens sent over 26 calls).

  Per-call output counts in the stream are partial snapshots, so only the run's output total is
  given. For Codex and every demo run, the meter says "not recorded" and lists the end-of-run
  counters as reported.
- **Prediction points.** These are the first tool call and every call whose phase differs from
  the previous call's. Each is a toolkit `[data-predict]` asking "What will it run next?", with
  gather, act and verify as the choices. The call's tool, input and text sit in the answer, and the
  lane hides the phase until the reveal.
- **Side by side.** A native checkbox shows the counterpart run from the other CLI next to the
  selected one: the same task, or the same demo, rehearsal and arm. Claude Code is on the left and
  Codex on the right, and each column has its own stepper, lane and meter. Claude Code's
  tool-search-off bomb arm has no Codex counterpart, and the note says so.
- Bomb runs keep the captures `<details>`. `<noscript>` gives the terminal replay commands and
  the path of the task JSON.

## Prose and source review

- Every number comes from a recording: tokens, times, exit codes and versions. None is
  illustrative, and the footer says so. The footer also says the lane's phases are the page's own
  reading of each call.
- The meter makes no context-window claim. Its bar is relative to the run's peak, and it says so.
- Gather, act, verify is credited to [How Claude Code works](https://code.claude.com/docs/en/how-claude-code-works).
  The re-sent transcript is credited to OpenAI's [Unrolling the Codex agent loop](https://openai.com/index/unrolling-the-codex-agent-loop/).
  Both are links only. The page makes no "latest" claims.
- No CLI is preferred over the other. Both harnesses have every task and demo, and side by side
  shows them as equals (ADR 0002).
