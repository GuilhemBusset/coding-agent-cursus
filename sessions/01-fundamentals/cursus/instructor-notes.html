Session 1 · Instructor · Notes

What students get wrong, what they ask, and the answers.

Grouped by act: the misconceptions to correct, the questions to expect, and every peer-instruction question in the decks and labs with its answer and why the other options are wrong.

Where the list comes from

The starting point is the 2025 primer’s list: the “Common Misconceptions To Correct” and “Anticipated Questions” sections of Instructor Guide: LLM Architecture Primer, in the 2025 agentic-or-workshop repository (file last changed 2026-03-07, accessed 2026-10-18). All six of its items appear below, marked 2025 primer, each placed in the act that teaches it and reworded for this session. The other items come from this session’s decks, labs and demo runbooks, each linked where it is taught.

Act I · The sampler

Misconceptions to correct

What students believeWhat to sayWhere
“LLMs output whole sentences at once.” 2025 primerOne token per loop step: sample, append, run the pass again. The factorization over tokens is exact, so nothing is lost by writing one token at a time.#pipeline, #append, tiny-LM lab
“Sampling is random guessing.” 2025 primerThe draw is constrained by the model’s probabilities. Temperature and top-p reshape that distribution; they do not replace it.#logits, next-token lab
“The model reads letters, so it should count them.”It receives integer IDs for sub-word chunks. Spelling facts come only from training text about those IDs, so counting is unreliable rather than impossible. Hand the counting to code.#tokenize, tokenizer lab, strawberry demo
“Two different answers to the same prompt mean a bug.”It is sampling. That is the root of the non-reproducibility Sessions 3 and 4 deal with.#sample, sampling demo
“A fluent answer is a correct one”, or “the next release will fix hallucination.”No training step installs a truth oracle, and there is no reserved mass for “I don’t know”. The base model’s false line about New Zealand reads exactly as fluently as its true one about Canberra.#weights
“A hard question gets more thought.”One forward pass uses the same layers once per token, whatever the question. Thinking longer needs more tokens: that is Act II.#system-1

Expected questions

Why does the attention lab show one lookup? Real models have many. 2025 primer
Yes: multi-head attention runs several lookups in parallel, each learning a different pattern; the slide’s source line counts 12 heads in each of GPT-2 small’s 12 layers. The lab shows one so the weights and the output can be read.
Why only one layer? 2025 primer
Real transformers stack many identical attention and feed-forward blocks; the 2025 primer gives about 32 for a 7B model and 80 or more for larger ones. One pass through one block is enough to show the flow.
Where does mixture-of-experts fit? 2025 primer
The 2025 misconception was “MoE changes the attention math”. It does not: MoE routes each token through some of several feed-forward experts, and the attention lookup is unchanged. This session does not teach MoE; answer in one sentence and move on.
Is temperature 0 deterministic?
In the tiny-LM lab, Argmax mode gives the same text every time. Neither agent CLI exposes a temperature setting (as of 2026-10-18, see the sampling runbook), so treat repeatability as something you measure, not something you assume.
Why does the strawberry demo use an invented word?
Current models have seen the strawberry question many times, so the real word would test recall instead of counting. The 300-letter word has 146 r’s.
Do I need both Claude Code and Codex?
No. You need one. Every instruction in this session works in either (ADR 0002).

Act II · Thinking

Misconceptions to correct

What students believeWhat to sayWhere
“Reasoning models have a separate System 2 module.”It is the same network, run for more passes. System 1 and System 2 are a metaphor, and the deck labels it as one.#system-1-2
“More samples always help, and a majority vote finds the truth.”A vote keeps the most common answer, even a common wrong one. Search is only as good as its verifier.best-of-N panel
“Maximum effort is the safe setting.”Accuracy can fall as the trace grows (inverse scaling), and easy problems get overthought. In the recorded effort demo both efforts were right; high effort only cost more tokens, time and money.#overthinking, effort demo
“The chain of thought shows how the model reached its answer.”Treat it as a lead, not as evidence. Models use hints they do not mention, especially when the hint arrives through tool output.#cot-faithfulness, #addition-36-59, #tool-cues
“RL has settled it: it makes models smarter.”Whether RL sharpens what the base model could already do or expands it is contested. Say so, and point to the illustrative panel.#sharpen-or-expand
“The agent knows my repository.”“World model” means three things. The one that matters on Monday, the agent’s picture of your repo, goes stale after every edit unless tools refresh it.#world-models, #repo-model

Expected questions

What does RL with verifiable rewards have to do with OR?
The reward is a checker: a test that passes or an answer that matches. Your solve contract is the same idea, used to judge an agent instead of to train it.
Which effort setting should I use?
The dial is an allowance, not a guarantee. Turn it up when the problem is hard and checkable, not by default, and measure it on your own task.
If the trace is not faithful, why read it at all?
It tells you where to look: which file, which assumption. Then you check that place yourself.

Act III · Agent = model + harness

Misconceptions to correct

What students believeWhat to sayWhere
“The model remembers our conversation.”The model is a pure function of its context. The harness re-sends the whole transcript every turn.#pure-function, #resend
“RAG happens after generation.” 2025 primerThe 2025 primer put retrieval before tokenization, as grounding context, and noted that real systems retrieve at different times. In an agent, retrieval is usually a tool call in the middle of the loop. Either way, retrieved text helps only once it is in the window for this call.#agent-loop, context lab
“A bigger window fixes forgetting.”The window is a budget shared by everything the harness loads, and quality degrades as it fills with noise. Compaction is lossy. Put a rule that must survive into AGENTS.md or CLAUDE.md, which the harness reloads.#context-window
“Prompt caching makes long sessions free.”Caching bills the repeated prefix at a lower rate, but the tokens are still sent and still fill the window.context lab, cost, #kv-cache
“The agent loop is the token loop.”The token loop of Act II writes one reply. The agent loop acts on real tools, observes real output and gets corrected by reality every turn.#agent-loop
“The agent stops when the task is done.”The model proposes to stop; the harness decides. Stop conditions fail two ways: the runaway loop, and victory declared while the tests are red.#stop-conditions
“A vendor’s benchmark table is what I will get.”Vendor tables mix settings and pick each model’s best run. A standardized run fixes the harness, effort and trials. Neither says how a model does on your task.#benchmarks

Expected questions

Should I send everything to subagents?
A subagent gets its own window, so exploration and long logs stay out of yours. But it spends its own tokens: it is a context tool, not a free lunch.
Is METR’s time horizon how long an agent can run?
No. It measures task difficulty in skilled-human time, at 50% reliability, on self-contained tasks that are cleaner than real work.
Why did the context bomb not make the agent forget?
With tool search on, these CLI versions no longer flood the window with the bomb’s tool descriptions, and both agents kept the opening rule in the recordings. The runbook says to report that honestly. In Claude Code the bomb still added about 1.7k tokens to every call (its instructions and tool names), and more than 23k with tool search off; in the Codex recordings the input did not change.
AGENTS.md or CLAUDE.md?
Write AGENTS.md, which both agents read, and make CLAUDE.md import it. This repository does exactly that.

Act IV · Drive it yourself

Misconceptions to correct

What students believeWhat to sayWhere
“The tests are green, so L2 is done.”Done means green, git diff --stat -- tests/ empty, and git status --short listing only M p00_model.py. Staged edits and new files show up only in git status.lab ladder, L2
“The done commands rule out cheating.”They cannot catch a model that returns the known optimum as a constant: the contract solves only the bundled instance. Read git diff -- p00_model.py.lab ladder, L2 hints
“The solver said Optimal, so the answer is right.”The status is a claim. The solve contract checks it against a whitelist and recomputes feasibility and the objective in plain code; a time-limit stop is slow, never Optimal.P00, L3 checker
“Plan mode wastes time.”It is the cheapest check there is: you review the plan before any file changes. In L3 the integrality and wraparound mistakes are cheaper to catch in the plan.lab ladder, L3

Expected questions

Can I turn in L3 from my partner’s laptop?
No. The driver copies solution.json and work/ into their own checkout, reruns uv run python check.py there, and turns in from their own laptop with /turn-in 01 or $turn-in 01.
Why work in an export instead of the course checkout?
The checkout holds the P00 instructor notes, which name the planted bugs. An agent that reads them is not exploring.
Are homework branches private?
No. The repository is public, so homework/s01/<handle> is public too.

Act V · When agents fail

Misconceptions to correct

What students believeWhat to sayWhere
“If the agent says all tests pass, the work is right.”Agents optimize what you check. Check that the verifier was not touched, then check the solution itself.#anchor, #gap
“More agents means more correct.”In the 2025 workshop, four cooperating agents dropped the CVaR term and still reported the same objective.#workshop
“A careful prompt stops prompt injection.”Not reliably. Remove one leg of the trifecta: untrusted input, private data, or a way to send data out.#trifecta
“A right answer is a verified answer.”A correct point with a broken certificate is still unverified (Agent D in the verifier-gaming lab).verifier-gaming lab

Expected questions

Is the verifier’s law a theorem?
No. It is a proposed rule from a blog post. The corollary for the course still holds: an agent gets good at whatever your verifier actually measures.
How do I keep secrets away from my agent?
Keep them out of the repository and out of the agent’s working directory, scope every token to the task, and scan before you push.

Peer-instruction questions, with answers

In the order they come up. The exit ticket in the close repeats one question per act. Without JavaScript the answers are visible at once, so take a show of hands before you scroll.

WhereQuestionAnswerWhy the other options are wrong
Opening, pollDevelopers forecast that AI would make them 24% faster. What did METR measure?Slower: 19% longer with AI allowed.“Much faster” and “about as forecast” repeat the feeling, which stayed wrong: afterwards they still believed in a 20% speedup. “No difference” is out because the interval, +2% to +39%, excludes zero. The 2026 follow-up is weak evidence by METR’s own account.
Act I, pipelineIs writing a text one token at a time a simplification that loses something?No. The factorization is exact (the chain rule).What limits a model is how well it learns each conditional, not the one-token-at-a-time form.
Tokenizer labHow many tokens is “ strawberry”, with its leading space?2 in this page’s illustrative tokenizer: “ straw” and “berry”.1 or 3 are what other real vocabularies might give; the lab says so. 11, one per character, is the misconception the lab exists to break.
Tokenizer labHow many r’s in “ strawberry” can the model see?None directly: it receives two integer IDs.Three, two and one all assume the model sees letters.
Act I, strawberrySame model, same question, five times, no tools: how many right?Whatever the live run gives. Recorded 2026-10-11: 3 of 5 for Claude Code (claude-haiku-5-5), 1 of 5 for Codex (gpt-6-luna).There is no fixed right number; that is the point. The pivot to code gets 146.
Act I, samplingSame prompt, same model, same settings, five times: how many different names?Recorded 2026-10-11: 5 distinct of 5 (Claude Code), 4 of 5 (Codex).Expecting one name assumes the model retrieves an answer instead of sampling one.
Exit ticket, Act IThe same prompt, run twice at temperature 0.7, gives two different objective values. Why?Sampling.A model update between two runs a minute apart is not the cause, and would not explain the spread on every rerun. Server load changes how long you wait; the tiny-LM lab shows the same spread on a model running in your browser. Memory of the first run: there is none between calls (Act III).
Best-of-N panelWith a 10% false-positive verifier, as N grows without bound, which curve’s limit is 100%?Coverage only.The verifier pick stays below 1 because the wrong samples it lets through grow with the right ones. Majority vote tends to the share of problems the model gets right more than half the time.
Exit ticket, Act IIWhich solves more hard problems: best-of-100 with majority vote, or best-of-5 with exact tests?Best-of-5 with exact tests.A vote keeps the most common answer, even a common wrong one. “About the same” ignores that an exact test keeps any candidate that passes.
Sharpen or expand panelAt k = 1,024, which model solves more problems in this illustrative mixture?The base model, about 96% against 73%.The RL-tuned model leads at k = 1, not at k = 1,024. They do not tie. The numbers come from a model built to show the debate, which is contested, not from measured data.
Effort-dial panelOn the inverse-scaling task, what does doubling thinking tokens past the peak do?Accuracy falls, and you pay double for it.“Keeps rising” is true only before the peak. “Flat and harmless” misses that each doubling past the peak costs accuracy. The curve is illustrative; the shape follows Gema et al.
Act II, think-pair-shareRecall or search, and where is your verifier?Open. A good answer names the task, says whether the agent recalls or searches, and names a check that does not trust the agent: a test, a checker, a certificate.A weak answer names no verifier, or names the agent’s own report.
Context lab, exit ticket, Act IIIMessage 30 is as long as message 1. Why does it cost more?The harness re-sends the whole transcript, so turn 30 carries every earlier message and reply as input.Later turns use the same model, at the same price per token. The model has no stored memory to search. Text does not tokenize into more tokens later. Earlier replies come back as input, not as output.
Exit ticket, Act IVThe agent says “fixed”. What makes L2 done?Green, and only p00_model.py changed, as git status --short shows.The summary is a claim. A green suite alone can come from edited tests, and git diff --stat misses staged test edits.
Verifier-gaming lab, certificatesAgents A to D each report “optimal”. Which are certified?Only B: feasible primal and dual, gap 0.A: the gap is 1, so 10 is not proven unreachable. C: x = 3 breaks x ≤ 2; an infeasible point can match any bound. D: the right point, but the dual breaks u + w ≥ 2, so its bound proves nothing.
Verifier-gaming lab, catch the agentThree patches all pass the test. Label each one.A edits the test, B is the honest fix, C hard-codes the value.A changes the expected value to the wrong answer the code already gives. C returns 5 only for the test’s input. A second test such as sum([7]) separates B from C.
Act V, peer question, exit ticket, Act VThe agent says “all tests pass”. What do you check first?Whether the verifier was touched, then the solution itself: a certificate, a bound, a duality gap.Asking the agent whether it is sure, or reading its summary, gets another self-report. Checking is often cheap.
