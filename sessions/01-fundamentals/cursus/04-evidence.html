Source: Ziqian Zhong, Aditi Raghunathan, Nicholas Carlini, ImpossibleBench: Measuring LLMs’ Propensity of Exploiting Test Cases, arXiv 2510.20270, 2025.

Speaker notes

Talk track: Level 2 practises habit 1, watch what it runs. ImpossibleBench, a 2025 benchmark, took real GitHub issues and changed their tests so no honest fix can pass. The rule says stop, but the agent had no way to; given one, a word that ends the run, GPT-5 fell to 9%: Act III’s “stop and report”.

Speaker notes

Talk track: the card you have been filling. Point at the columns: the claim; the command you ran and what it printed; match; what is still uncertain after the check. Point at the pink row: mine, from a 2025 workshop, told from memory, with no transcript. Four cooperating agents worked on a model whose objective had a CVaR term, conditional value at risk, the part that prices the worst outcomes. They silently dropped that term and still reported the same objective, so the model they solved had no CVaR in it. More agents did not mean more correct. The check is to recompute the objective from the stated model, every term included.

The generator-verifier gap

Finding the plan took a solver; checking it takes sums.

P1 + P2’s cheapest routes, demand × unit cost: 20·2 + 30·3 + 25·2 + 15·3 + 10·6 = 285. That plan fits capacity: P1 serves C1, C2: 50 ≤ 70; P2 serves C3, C4, C5: 50 ≤ 60.

Speaker notes

Talk track: Act III ended one run on a sentence: no plan exists below 485. Anyone can check it. Point at the rows: each set of open plants, its fixed costs, plus every customer sent down its cheapest open route. Ignoring capacity can only make it cheaper, so this is a floor: no real plan with those plants costs less. Point at “one plant”: none holds 100. Point at the dot and the line under the chart: the cheapest-route plan for P1 + P2 also fits capacity, so it costs exactly the smallest bound and nothing beats it. Act III’s 400 sits in the empty zone.

Finding that plan took HiGHS, a mixed-integer solver; checking it took arithmetic. That gap is why habit 5 pays: generating is hard, checking is cheap. Operations research has long worked this way, with bounds, gaps and certificates; the duals in this morning’s cold open were one such certificate.

Activity: check the top row with the room, from the line under the chart: forty, ninety, fifty, forty-five, sixty: 285; plus 200 fixed: 485.

Transition: “Checking is cheap once someone has built the check. Who builds it in this repository?”

This repository · An instruction asks

An instruction asks; this repository’s gates decide.

The gates decide how a change lands, not whether it is right: a green check covers only what the tests test.

Speaker notes

Talk track: remember Act III: an instruction asks; the harness decides. Point at the amber box: AGENTS.md asks every agent to land each change by pull request; it only asks. Point at the open locks: git hooks in your clone refuse a commit on main and a push to main, but --no-verify skips them.

Point at the teal box: the ruleset on GitHub. Main takes a change only as a pull request whose required check is green; no push to main, no force-push, no deletion. Point at the 0: nobody is exempt, no role, no app. Point at the audit: it only reports.

Point at the last line: with no approvals required, a green check is all a pull request needs here, and green covers only what the tests test: remember fix C.
