Exit ticket · Acts I and II Lock in before anyone reveals.

Act I · The same prompt, run twice at temperature 0.7, gives two different objective values. Why?

Each run draws tokens from the same distribution, so two runs can differ. Sampling, not retrieval.

Act II · Which solves more hard problems?

A vote keeps the most common answer, even a common wrong one; an exact test keeps only a candidate that passes. Search is only as good as its verifier.

Speaker notes

Talk track: five questions before you go, one or two per act. Read each question aloud. Hands up for each choice; select the room’s majority on each question and press Lock in. Only then press Reveal.

Act I. Sampling. Each run draws its tokens from the same distribution, so two runs can differ: sampling, not retrieval. A model update between two back-to-back runs would not explain a spread on every rerun; server load changes how long you wait, and the tiny-LM lab shows the same spread on a model in your browser; and there is no memory between calls.

Act II. Best-of-5 with exact tests. A vote keeps the most common answer, even a common wrong one; an exact test keeps any candidate that passes. Search is only as good as its verifier.

Exit ticket · Act IV Lock in before anyone reveals.

Act IV · The agent says “all tests pass”. What do you check first?

Agents optimize what you check. Read the diff for changes to the tests or checker, then check the solution independently: a certificate, a bound, a duality gap. Checking is often cheap.

Speaker notes

Talk track: the last question. Hands, lock in, then Reveal.

Act IV. Whether the verifier was touched, then the solution itself. Agents optimize what you check, so first read the diff for changes to the tests or the checker; in Act IV, the given files stay unchanged. Then check the solution on its own: a certificate, a bound, a duality gap. Asking the agent whether it is sure, or reading its summary, only gets another self-report. Checking is often cheap.

Homework

Your homework: solve P01 with your agent, then turn it in.

Speaker notes

Talk track: your homework is one exercise, P01, the bigger problem from Act IV’s last slide: 40 legs, 10 electric trucks, eight depots. The steps are the five you just used: read, plan, build, check, ship.

Solve: the sheet, exercises/home.html, has the plan prompt; exercises/homework-p01/ has the statement, the data and the checker. Your agent writes the model; you set the contract.

Check: done means the checker, run by you, proves the plan feasible: every feasibility contract passes, and PASS if it is optimal too. Grading reruns the checker from main on your solution.json, then reads your model. A feasible plan stopped at a time limit, with only optimality failing, beats a cheaper plan that breaks a contract.

Turn in: the same command as in class, a new commit on your branch, homework/s01/ and your handle. Run it as often as you like. The branch is public, so keep secrets out of your notes.

Background for you, not for the slides: the turn-in rules are ADR 0009, docs/adr/0009-homework-on-per-student-branches.md.
