Speaker notes · 0.5 min

Second anchor of the day. Act I and II were about the model: a sampler, and what more tokens buy. Now: what turns that sampler into something that edits your repo and runs your solver.

01 · The second anchor

The model is a pure function of its context.

No memory between calls. What the model “knows” for this call is in the window right now: that is all “in-context” means. The randomness you saw in Act I is in the sampling, not in a hidden state.

Source: Anthropic, How Claude Code uses prompt caching, “The model doesn’t remember anything between requests”, code.claude.com, read 2026-10-18.

Driving: if the agent needs to know it, it has to be in the context: in the prompt, in a file it reads, or in an instruction file.

Speaker notes · 2 min

The most important idea of the day. Write f(context) → p(next token) on the board. Same weights, same context, same distribution; different answers come from sampling.

Ask: then where does the chat’s memory live? Not in the model. Let them guess “the harness” before the next slide.

02 · The conversation is an illusion

The harness re-sends the whole transcript, every turn.

  1. Call 1system + toolsinstructionsyour prompt
  2. Call 2system + toolsinstructionsyour prompttool calltool result
  3. Call 3system + toolsinstructionsyour prompttool calltool resultreplyyour next message

New content is appended at the end; most of each request is identical to the one before. Measured in a recording: Claude Code’s 26 calls on one task sent 15,654 tokens on the first call and 373,202 on the last, every call carrying everything before it.

Sources: Anthropic, How Claude Code uses prompt caching, §How the cache is organized, code.claude.com, read 2026-10-18. Recording context-bomb-claude, Claude Code 2.1.301, 2026-10-16, replay.

Driving: every old turn is still being paid for and still competing for attention. Start a fresh session per task.

Speaker notes · 2 min

Walk down the three bars. The highlighted cell is the only new thing; everything to its left is re-sent. This is how a stateless function holds a conversation.

The numbers are per-call input as Claude Code reported it in the recorded context-bomb task (fixtures/runs). Input here includes cached input; the next slides split the two.

03 · A finite buffer

The context window is a budget that fills.

  • Spent before you type: system prompt, tool definitions, instruction files, skill descriptions. In the bomb recordings, Claude Code’s /context read 13k tokens in use before the question; Codex’s /status read 13.8K used of 828K.
  • When it fills, the harness compacts: it replaces the conversation with a summary. /compact does it by hand in both CLIs.
  • What survives: Claude Code re-reads the project-root CLAUDE.md after compacting. An instruction given only in the chat can be lost.

Lab · the budget

Open Context lab · The context budget and fill it: read a log, add an MCP server, then compact or clear. Illustrative numbers.

Sources: Anthropic, Manage Claude’s memory, code.claude.com; OpenAI, Slash commands in Codex CLI (/compact, /status), learn.chatgpt.com; both read 2026-10-18. Captures: cursus/demos/agent/recorded/, 2026-10-16.

Driving: read /context (Claude Code) or /status (Codex) before a long task. Put rules that must last in an instruction file, not in the chat.

Speaker notes · 1.5 min

Current models have 1M-token windows (landscape part), but the size is not the point: the window is shared by everything the harness loads, and quality degrades as it fills with noise.

Compaction is lossy by design. The fix for “it forgot my rule” is to move the rule into AGENTS.md or CLAUDE.md, which the harness reloads.

04 · Cost grows with the transcript · Lab

Why message 30 costs more than message 1.

Two messages of the same length cost different amounts, because each call re-reads everything before it. Total input grows roughly with the square of the number of turns.

  • Recorded, Claude Code: 26 calls; the largest context was 373,202 tokens, but 4,889,658 input tokens were sent in total.
  • Recorded, Codex, same task: 2,982,361 input tokens in total.

Lab · predict first

Open Context lab · What it costs over thirty turns. Lock in its predict question, then move the turn slider and compare the curves with and without caching. Illustrative constants.

Source: recordings context-bomb-claude (claude-opus-5-5) and context-bomb-codex (gpt-6-astra), medium effort, 2026-10-16, totals as each CLI reported them; replay with the token meter.

Driving: long sessions get slower and dearer per message. Finish a task, then clear or start fresh rather than piling the next one on.

Speaker notes · 4 min

1 min, the slide. With a prefix P and u new tokens per turn, turn t sends about P + t·u, so n turns send about n·P + u·n²/2. The recorded run is the real thing: 24 large logs read one by one.

3 min, lab. Students open panel 2 of the context lab on their laptops, lock in the predict answer, then reveal. Move the turn slider, switch the plot between cost and tokens, and compare the two curves: with caching the bill falls while the tokens sent stay the same. That is the bridge to the next slide.

05 · The KV cache

The KV cache is memoization of a prefix already processed.

  • Inside a call, attention keeps each processed token’s keys and values, so later tokens do not recompute them.
  • Across calls, prompt caching keeps that work for a prefix: the next request is matched against it, and only what changed is fully processed.
  • Exact match: change anything early in the request (the model, the system prompt, the tool set) and everything after it is recomputed.

Driving: pick the model at the start; switching it mid-task recomputes the whole prefix, and so does adding an MCP server when its tools load upfront (tool search off). In Claude Code, changing effort on Opus 5.5 or Haiku 5.5 (API key or subscription) keeps the cache, and so does editing the root CLAUDE.md: the edit waits for /clear, /compact or a restart.

Speaker notes · 2 min

For this audience: memoization keyed on the exact prefix. A function call you already evaluated is looked up, not recomputed. Billing makes it visible: a cache hit costs 5% of base input on Opus 5.5 and 10% on GPT-6 Astra.

Estimate, not a bill: at Opus 5.5 list prices the recorded run’s 4.89M input tokens would cost about $19.56 uncached; with 4.50M as cache hits ($0.90) and the remaining 0.39M at most at the 5-minute write rate ($1.96), about $2.86. The normalized run does not split cache writes from fresh input, hence “at most”.

Claude Code’s doc says a CLAUDE.md edit does not apply mid-session for exactly this reason.

06 · The outer loop

An agent runs tools in a loop: gather, act, verify.

ReAct interleaves reasoning traces with actions: the reasoning tracks and updates the plan, the actions fetch information from outside. Not Act II’s token loop: here each turn acts on real tools and is corrected by real output.

Sources: Shunyu Yao et al., ReAct: Synergizing Reasoning and Acting in Language Models, arXiv 2210.03629, v1 2022-10-06, abstract. Simon Willison, What is agentic engineering?, “Agents run tools in a loop to achieve a goal”, simonwillison.net, updated 2026-03-15.

Driving: the loop is only as good as its verify step. Give the agent one fast command that says pass or fail.

Speaker notes · 2 min

The shape is old: perceive, plan, act, observe (Russell and Norvig). ReAct is its LLM form. The harness calls the model, executes the tool calls it asks for, appends the results and calls it again.

Contrast with Act II: a chatbot’s reply is also many forward passes, but nothing outside the model checks it. Here reality answers back every turn. The replay widget shows the gather, act and verify lane for any recording.

08 · When to stop

Stop conditions are harness, and they fail two ways.

The runaway loop

It never converges: the same failing command again, edit and revert, one more search. Every turn re-sends the transcript, so the bill climbs. Illustrative pattern.

Brakes: claude -p --max-turns and --max-budget-usd; in any CLI, you interrupt.

Premature victory

“All tests pass” while they are red, or green because a test was weakened. Illustrative pattern; Act V shows real cases.

Brakes: a Stop hook (both CLIs) that runs the tests; you read the test run and the diff, not the summary.

Recorded, a good stop: a budget test asks for cost ≤ 400 when the proven optimum is 485. Both agents changed nothing and reported the conflict (Claude Code, Codex).

Sources, read 2026-10-18: Anthropic, CLI reference, code.claude.com; Anthropic, Hooks reference, code.claude.com; OpenAI, Hooks, learn.chatgpt.com. Recordings impossible-*, 2026-10-16.

Driving: decide before the run what “done” means and what makes it stop. The agent’s “done” is a claim; the check is the evidence.

Speaker notes · 2 min

The model proposes to stop by answering without a tool call; the harness decides whether that ends the run. Caps, hooks and you are all harness.

The impossible task is unedited: the prompt neither invites nor forbids a hack. Both cited the contract that pins 485; Claude Code also derived a lower bound of 445 for any plan. Both stopped with pytest still red. One recording is a case, not a rate; Act V is about the runs that do not stop this well.

09 · Harness · Instruction files

AGENTS.md and CLAUDE.md: a README for the agent, loaded every session.

  • AGENTS.md is an open format: setup commands, how to run the tests, conventions. Codex reads every AGENTS.md from the project root down to the working folder, joined in that order, up to 32 KiB by default.
  • CLAUDE.md is Claude Code’s file, read at the start of every session. Claude Code can also read a repository’s AGENTS.md in its place. This course repo’s CLAUDE.md is one line: @AGENTS.md.
  • The files sit in the prefix of every call: they cost tokens each turn and steer every step.

Governance

AGENTS.md, contributed by OpenAI, is a founding project of the Agentic AI Foundation under the Linux Foundation (next slide).

Sources, read 2026-10-18: AGENTS.md, agents.md; OpenAI, Custom instructions with AGENTS.md, learn.chatgpt.com; Anthropic, Manage Claude’s memory, §AGENTS.md, code.claude.com.

Driving: keep instruction files lean: how to build, how to test, what never to touch. Every line is paid for on every call.

Speaker notes · 2 min

One file both agents read is the ADR 0002 answer to “students have Claude Code or Codex, not both”: write AGENTS.md, and make CLAUDE.md import it.

Lean matters twice: the file is re-sent each call (cost), and a long file dilutes the rules that matter (attention). Put the test command first.

10 · Harness · Skills and MCP

Skills load know-how on demand; MCP plugs in tools.

Skills · open Agent Skills standard

A skill is a folder with a SKILL.md (name, description, instructions) plus optional scripts and references. At startup the agent loads only names and descriptions; the full instructions load when a task matches.

Originally developed by Anthropic, released as an open standard. Claude Code and Codex skills both follow it.

MCP · Model Context Protocol

A protocol for connecting agents to servers that expose tools and data. Each server’s instructions and tool definitions take room in the context.

On 2025-12-09 Anthropic donated MCP to the Agentic AI Foundation, a directed fund under the Linux Foundation co-founded by Anthropic, Block and OpenAI. Founding projects: MCP, goose and AGENTS.md.

Sources: Agent Skills, agentskills.io, read 2026-10-18; Anthropic, Skills, code.claude.com; OpenAI, Build skills, learn.chatgpt.com; David Soria Parra, MCP joins the Agentic AI Foundation, blog.modelcontextprotocol.io, 2025-12-09.

Driving: turn a procedure you repeat into a skill; add an MCP server only when you need its tools, and check what it costs with /context or /mcp.

Speaker notes · 2 min

Skills are progressive disclosure: a one-line description is always in context, the body only when used. That is why many skills are cheap and many verbose MCP servers are not.

The foundation matters for longevity: MCP and AGENTS.md now have vendor-neutral governance, and the MCP maintainers keep the technical direction. Bridge: what does a noisy server cost? The next demo.

12 · Harness · Subagents and hooks

Subagents get their own window; hooks run code you trust.

Subagents

A subagent starts with a fresh, separate context window, does the side task (exploring, searching, reading logs) and returns only a summary. Your main window stays for requirements and decisions.

Claude Code delegates to subagents by description; Codex spawns them in parallel and collects their results.

Hooks

Scripts the harness runs at fixed points of the loop: session start, before and after a tool call, when the agent stops. A PreToolUse hook can block a call.

Instructions ask; hooks enforce. Same idea as this repo’s git hooks, which block commits on main for any agent.

Sources, read 2026-10-18: Anthropic, Subagents, code.claude.com; OpenAI, Subagents, learn.chatgpt.com; Anthropic, Hooks reference, code.claude.com; OpenAI, Hooks, learn.chatgpt.com.

Driving: send exploration to a subagent; turn any rule you cannot afford to be ignored into a hook or a check.

Speaker notes · 2 min

Hold onto the subagent point: independent work such as a search, a plot or reading a long log does not need to share your window. Only the summary comes back. It costs tokens of its own, so it is a context tool, not a free lunch.

Hooks are deterministic: they run whether or not the model remembers. AGENTS.md here describes the same split: no per-agent guard layer, but git hooks and a server-side ruleset every agent hits.

Speaker notes · 2 min

Headless is where autonomy jumps: no one watches each step. That is the one discipline again: autonomy never past your ability to verify.

14 · The 2026 landscape As of 2026-10-18

The paradigm ladder: each rung hands over more of the loop.

  1. 1AutocompleteFinishes the line you type
  2. 2ChatAnswers and snippets you paste
  3. 3Agentic CLIReads, runs and edits in your repo: Claude Code, Codex
  4. 4Background and cloud agentsA task runs in a cloud sandbox and comes back as a branch or PR
  5. 5FleetsMany agents in parallel, coordinated, reviewed as a batch

Each rung up, you review fewer steps and more results. The verification has to climb with it.

Product pages, read 2026-10-18: Anthropic, Use Claude Code in the cloud, code.claude.com, and Run agents in parallel, code.claude.com; OpenAI, Codex Cloud, learn.chatgpt.com, and Subagents, learn.chatgpt.com. The ladder is this course’s framing.

Driving: climb one rung only when you can check its output at that rung’s speed.

Speaker notes · 1 min

Today we live on rung 3. Rungs 4 and 5 exist in both vendors’ products as of this date: cloud sessions that return pull requests, and parallel agents (Claude Code agent teams and projects, Codex subagents and its Ultra mode).

The ladder is a teaching framing, not a vendor taxonomy.

16 · The 2026 landscape As of 2026-10-18

METR’s time horizon: the trend line to watch.

Task length, in skilled-human time, that an agent finishes half the time: GPT-4 about 4 minutes, Claude Mythos Preview (early) about 17 hours. Doubling time: about 7 months since 2019, 131 days since 2023.

Sources: METR, Time Horizon 1.1, metr.org, 2026-01-29; METR, Time horizons data, metr.org, last updated 2026-09-08, no longer maintained.

Driving: the tasks agents finish grow fast, and so must your checks. Plan the verification for the task length you delegate.

Speaker notes · 2 min

Definition: fit success against human task length per model; the 50% horizon is where the fitted curve crosses 50%. It measures task difficulty, not how long the agent runs.

Caveats to say aloud: 50% reliability, not 99%; tasks are self-contained, well-specified software, ML and security tasks, cleaner than real work; METR calls measurements above 16 hours unreliable on this suite, and the two newest points have very wide intervals. Since 2024 the TH1.1 doubling time is 89 days. The page stopped being updated on 2026-09-08, so newer models are not on it.

Why this and not a leaderboard: an independent lab, one method, one trend. The next slide shows why vendor tables need care.

18 · The 2026 landscape As of 2026-10-18

Vibe coding or agentic engineering: the difference is review.

Vibe coding · February 2025

“fully give in to the vibes, embrace exponentials, and forget that the code even exists”

Andrej Karpathy’s coinage: accept all, don’t read the diffs. Fine for a throwaway prototype.

Agentic engineering

Developing software with coding agents while you still own the result: give them tools, specify the problem at the right level of detail, then verify and iterate until you are confident it works.

By early 2026 the name for professional work with agents, used by Karpathy and Willison among others.

Sources: Andrej Karpathy, post on X, 2025-02-02, quoted in Simon Willison, Not all AI-assisted programming is vibe coding, simonwillison.net, 2025-03-19; Simon Willison, What is agentic engineering?, simonwillison.net, updated 2026-03-15, and GLM-5: From Vibe Coding to Agentic Engineering, simonwillison.net, 2026-02-11.

Driving: the same agent can do either. What makes it engineering is what you check before you accept.

Speaker notes · 1 min

Back to the one discipline: never raise autonomy past your ability to verify the solution, not just the code. Vibe coding is autonomy with no verification; that is a choice you can make for a prototype, never for a model that ships a number to a planner.

Willison noted on 2026-02-11 that “agentic engineering” was showing up in several places, most notably from Karpathy and Addy Osmani. The vibe-coding quote is Karpathy’s original post as Willison reproduces it.
