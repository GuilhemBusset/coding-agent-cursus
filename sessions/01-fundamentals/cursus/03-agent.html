Act III · What is an agent?

An agent runs tools in a loop to reach a goal.

  1. 1 · The model. Text in, text out: alone, it runs nothing.
  2. 2 · + Tools. It writes a tool call; the harness runs it.
  3. 3 · + A loop. The result goes back in, until a reply has no tool call.
  4. 4 · = An agent. The harness is everything but the model.

Source: Simon Willison, What is agentic engineering?, simonwillison.net, 2026; “harness”: Anthropic, How Claude Code works, code.claude.com.

Speaker notes

Talk track: Act II ended on a question: “The model only writes text. So who ran the solver in the cold open?” Not the model. This slide builds the answer, one part at a time; press each step as you say it.

Step 1, the model: Acts I and II in one box. It reads its context, here only your goal, and writes text. Alone, it cannot open a file or run a test; a chatbot is this box.

Step 2, tools. The harness lists the tools in the context: Read, Edit, Bash, Search. Now the model can write a tool call: a structured request, a tool name and its input, as text the harness can parse. The harness runs it on your repo. The model still only wrote text.

Step 3, a loop. The result is appended to the context and the harness calls the model again, with everything so far. Round and round, until a reply holds no tool call: that reply goes to you, and the run stops. This is the agent loop. Do not confuse it with Act II’s token loop, which writes one reply inside the Model box.

Step 4, the harness: everything but the model. It builds the context, loads your rules and AGENTS.md, lists the tools, decides what may run, runs it, loops and stops. Claude Code and Codex are harnesses. Agent = model + harness: if it is not the model, it is the harness.

Read the headline: an agent runs tools in a loop to reach a goal. Every part of this picture is one of the act’s five questions, and the next slide numbers them.

Think-pair-share: “On your own task, what could check the agent’s answer, and how often does it see that check?” Alone first, then with your neighbour. Listen for pairs with no check: Act IV is about them.

Transition: “That is the picture. Now one real run of it.”

Background for you, not for the slides: the headline paraphrases Simon Willison, “Agents run tools in a loop to achieve a goal” (What is agentic engineering?, updated 2026-03-15). Claude Code’s docs name the parts: models that reason, tools that act, and “the layer around the model that provides the tools and manages the context the model sees”, the agentic harness (How Claude Code works). Anthropic’s Building effective agents (2024-12-19) says the same in one line: LLMs “using tools based on environmental feedback in a loop”. The shape is older: Russell and Norvig’s agent perceives its environment and acts on it, and ReAct (Yao et al., 2022) interleaves reasoning with acting.

Part 2 · What does each call see? · What it costs

Call 26 sends 24× the tokens. Does it cost 24×?

  1. 1 · At full price. Each call re-sends the whole run.
  2. 2 · With the cache. Re-sent tokens cost a twentieth; you pay for what is new.
  3. 3 · After a break. The cache expired: the next call writes it all again.

Speaker notes

Talk track: same bars as before, now in dollars, on a longer task: 26 calls reading 24 logs. Call 26 sends 373,202 tokens, 24 times call 1. Ask the room: does it cost 24 times as much? Press 1, At full price. The amber line is what each call would cost with nothing cached, every input token at $4 per million: $0.06 for call 1, $1.49 for call 26, $19.65 for the run. It is computed, not billed.

Press 2, With the cache. Grey is the re-sent run, read from the cache at $0.20 per million, a twentieth of the price. Teal is what is new, written to the cache at $8 per million. Call 26: 358,378 re-sent cost $0.07, the 14,822 new cost $0.12. Billed for the run: $4.13; call 26 cost about 4 times call 1, not 24. Point at calls 4 and 6: the cache missed, the new part was written twice, and each cost more than call 26. Cheaper is not smaller: those tokens still fill the window.

Press 3, After a break. Claude Code asked for an hour of cache here; the API’s default is shorter. Any change early in the context, another model, another tool, breaks everything after it. A 27th call after lunch writes all 373,202 tokens again: about $3, computed.

Activity: “Your session has been open since this morning, and you ask it something unrelated. What does that cost, and what would you do instead?” Listen for: a fresh session, habit 2.

Transition: “Cached tokens are cheap, but they still fill the window. What is in it, and does the model use all of it equally?”

Background for you, not for the slides: fixtures/runs/raw/context-bomb-claude.jsonl (Claude Code 2.1.301, Opus 5.5, 2026-10-16), whose usage blocks give each call’s cache reads and writes; this run wrote with the 1-hour time to live. Opus 5.5 list prices as of 2026-10-18: input $4, cache read $0.20, cache write $5 (default lifetime) or $8 (1 hour), output $20 per million. The CLI’s own total_cost_usd is $4.13; writes are $3.14 of it. The chart leaves out output tokens, $0.09 for the whole run; the full-price total includes them. On a subscription the same tokens draw down your usage limits instead of dollars.

Each rung hands more of the loop to the agent.

Each rung up, you review fewer steps and bigger results: your checks must climb too.

Speaker notes
