Pre-work: set up your machine

Installing and logging in is where a hands-on session loses its first hour. Do it a few days before Session 1: install the tools, log in to your agent, run the setup check, and paste its summary into your instructor's form. Then do the reading.

What you need

You need one coding agent: Claude Code or Codex. Both are fine, and neither is required on top of the other. Everything in the course works with either one.

  1. Install the tools: git, the GitHub CLI (gh), uv, mise, and your agent. About 30 to 45 minutes.
  2. Log in to GitHub and to your agent.
  3. Run the setup check and paste its summary block into the form your instructor gives you.
  4. Do the reading: about 2 to 3 hours, video and course included.

Which terminal?

  • macOS: Terminal (or any terminal you like).
  • Linux: your usual shell.
  • WSL: the terminal of your WSL 2 distribution, for example Ubuntu. Install WSL 2 itself with Microsoft's WSL guide. If you choose WSL, install every tool inside WSL and keep your course clone there.
  • Windows: PowerShell for the install commands (no need to run it as administrator). Installing Git for Windows also gives you Git Bash: use Git Bash for every bash … command in the course. After each install, open a new terminal window, not just a new tab, so that your PATH includes the new tool.

Linux and WSL

Debian, Ubuntu, and the default Ubuntu in WSL. This adds GitHub's own package repository, then installs gh from it. Paste it as one command:

(type -p wget >/dev/null || (sudo apt update && sudo apt install wget -y)) \
  && sudo mkdir -p -m 755 /etc/apt/keyrings \
  && out=$(mktemp) && wget -nv -O$out https://cli.github.com/packages/githubcli-archive-keyring.gpg \
  && cat $out | sudo tee /etc/apt/keyrings/githubcli-archive-keyring.gpg > /dev/null \
  && sudo chmod go+r /etc/apt/keyrings/githubcli-archive-keyring.gpg \
  && sudo mkdir -p -m 755 /etc/apt/sources.list.d \
  && echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/githubcli-archive-keyring.gpg] https://cli.github.com/packages stable main" | sudo tee /etc/apt/sources.list.d/github-cli.list > /dev/null \
  && sudo apt update \
  && sudo apt install gh -y

Fedora (DNF5):

sudo dnf install dnf5-plugins
sudo dnf config-manager addrepo --from-repofile=https://cli.github.com/packages/rpm/gh-cli.repo

Login troubleshooting

No browser opens, or it opens on the wrong machine. The login command always prints a URL. Copy it by hand and paste it into a browser where you are signed in. In Claude Code, press c to copy the login URL. To copy from a terminal yourself, select the text, then use Cmd+C on macOS or Ctrl+Shift+C in Linux, WSL and Windows Terminal. A long URL may wrap across several lines: copy all of it, with no spaces or line breaks.

The browser shows a code instead of returning to the terminal. This is common in WSL 2. Paste that code into the terminal at the Paste code here if prompted prompt (Claude Code). For Codex, use device code login instead: turn on device code login in your ChatGPT security settings, then run the command below, open the link it prints by hand and enter the one-time code.

codex login --device-auth

Claude Code uses an old API key instead of your subscription. If ANTHROPIC_API_KEY is set, Claude Code uses it once you approve it, and always in non-interactive mode (claude -p, which the setup check uses). A stale or expired key then fails even though your subscription is fine. The setup check tells you when the variable is set, without showing its value. Remove it:

bash or zsh (macOS, Linux, WSL, Git Bash)

unset ANTHROPIC_API_KEY
grep -n ANTHROPIC_API_KEY ~/.bashrc ~/.bash_profile ~/.zshrc ~/.profile

The first line removes it from this terminal. The second shows where your shell config files (rc files such as ~/.bashrc or ~/.zshrc) set it: delete that line, then open a new terminal.

PowerShell (Windows)

Remove-Item Env:ANTHROPIC_API_KEY
[Environment]::SetEnvironmentVariable("ANTHROPIC_API_KEY", $null, "User")

The first line removes it from this window. The second removes it from your Windows user environment variables, where it survives restarts (also under Settings, “Edit environment variables for your account”). Then open a new terminal.

Then run claude again and check /status.

Run the setup check

1. Clone the course and set up Session 1

gh repo clone GuilhemBusset/coding-agent-cursus
cd coding-agent-cursus
bash setup/session-01-fundamentals.sh

On Windows, run these in Git Bash. The last line uses mise to set up the Python and uv versions Session 1 pins, then its Python packages.

2. Run the check

From the root of your clone. In bash or zsh (macOS, Linux, WSL) or in Git Bash on Windows:

bash sessions/01-fundamentals/exercises/check-setup.sh

Or in Windows PowerShell:

powershell -NoProfile -ExecutionPolicy Bypass -File .\sessions\01-fundamentals\exercises\check-setup.ps1

Both run the same checks, from check_setup.py in the same folder, through uv. The first run may download Python 3.12, and the agent smoke test can take a minute or two.

3. Read the result

Each line reads <check>: PASS, <check>: FAIL with a hint, or <agent>: not installed (fine) for the agent you do not use. The script exits non-zero if any line is FAIL.

What each check verifies
CheckPASS means
git, gh, uv, miseFound, at or above the minimum version: git 2.23, gh 2.0, uv 0.5, mise 2024.1.0.
git-identityuser.name and user.email are set. Their values are not printed.
network <host>The host answered an HTTPS request within 10 seconds: github.com, api.github.com and pypi.org, plus api.anthropic.com or api.openai.com for your agent.
gh-authgh auth status succeeds. Its output, which can include your token, is never printed.
pushYou can push a branch for /turn-in (see below).
claude, codexThe agent is installed and prints a version. The one you do not use reads not installed (fine).
claude-smoke, codex-smokeAsked to “Reply with exactly: OK”, the agent replied exactly OK, so it is installed and logged in.
agentAt least one of Claude Code and Codex is installed. FAIL only if neither is.

The push check uses a temporary branch

To prove that /turn-in will work, the check pushes an empty commit to a temporary branch setup-check/<your GitHub handle>, checks that it arrived, then deletes it if it still holds that test commit. If you cannot push to the course repository, it uses your fork instead, exactly as turn-in does, and creates the fork with gh if you do not have one yet. It never touches your own branches, commits, staged changes or files. If the branch is left behind, a note: line says why and when it is safe to remove it.

4. Paste the summary

The check ends with a block between ----- BEGIN SETUP SUMMARY ----- and ----- END SETUP SUMMARY -----. Copy the whole block, both marker lines included, and paste it into the form your instructor gives you. It contains no secrets: no token, key or remote URL. Here is an illustrative block (yours will differ):

----- BEGIN SETUP SUMMARY -----
date: 2026-10-10 (UTC)
os: Linux (WSL)
kernel: 6.18.33.2-microsoft-standard-WSL2
python: 3.12.13
script: check_setup.py sha256 <hash>
github: your-handle
git: PASS 2.53.0 (>= 2.23.0)
git-identity: PASS user.name and user.email are set
gh: PASS 2.65.1 (>= 2.0.0)
uv: PASS 0.11.28 (>= 0.5.0)
mise: PASS 2026.7.0 (>= 2024.1.0)
network github.com: PASS reachable (HTTP 200)
network api.github.com: PASS reachable (HTTP 200)
network pypi.org: PASS reachable (HTTP 200)
network api.anthropic.com: PASS reachable (HTTP 404)
gh-auth: PASS logged in to GitHub
push: PASS to your-handle/coding-agent-cursus (your fork; turn-in will use it)
claude: PASS 2.1.296
claude-smoke: PASS replied OK
codex: not installed (fine)
agent: PASS Claude Code
result: PASS
----- END SETUP SUMMARY -----

If you can push to the course repository itself, the push line ends with (course repo) instead. Any HTTP status, even 404, counts as reachable: the check only needs an answer.

If a line is FAIL

  • A tool: install or update it (Install the tools), open a new terminal, rerun.
  • network: try another network. On a campus or company network, ask whether HTTPS goes through a proxy, and set HTTPS_PROXY if so.
  • gh-auth: run gh auth login.
  • push: run gh auth setup-git if your clone uses HTTPS, or check your SSH key if it uses SSH, then rerun. The FAIL line says which repository it tried.
  • claude-smoke or codex-smoke: see Login troubleshooting.
  • uv or checker (the check could not start): install uv, open a new terminal and rerun. Even then the block lists which tools were found; paste it anyway.

Still stuck? Paste the block into the form anyway and tell your instructor which line fails: that is what the block is for.
